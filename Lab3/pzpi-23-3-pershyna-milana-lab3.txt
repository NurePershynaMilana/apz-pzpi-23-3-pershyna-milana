2 ЗАВДАННЯ
Ознайомитися з процесом розробки front-end частини програмної системи з використанням сучасних бібліотек та архітектурних підходів. Отримати практичні навички реалізації веб-клієнта у складі розподіленої IoT-системи, що взаємодіє з серверною частиною через REST API.
Розробити веб-застосунок Plant Care System на основі React.js, TypeScript, Material-UI та Redux як частину системи моніторингу та догляду за кімнатними рослинами. Застосунок повинен підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий для адміністраторів. Обидва інтерфейси повинні підтримувати інтернаціоналізацію та локалізацію: українську та англійську мови, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту.
Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи (рослини, типи рослин, сенсори), створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.
Звіт повинен містити: опис прийнятих інженерних рішень, опис взаємодії компонентів, UML-діаграму прецедентів (Use Case Diagram), UML-діаграму компонентів (Component Diagram), діаграму пакетів (Package Diagram) та діаграму діяльності (Activity Diagram).

3. ОПИС ВИКОНАНОЇ РОБОТИ
Розроблено повнофункціональний веб-застосунок Plant Care для моніторингу та догляду за кімнатними рослинами через IoT-датчики. Застосунок є веб-клієнтом системи Plant Care System і взаємодіє з серверним API на Node.js/Express/PostgreSQL. Реалізовано окремі інтерфейси для користувачів та адміністраторів, повна локалізація UA/EN, графіки Recharts для відображення даних сенсорів, PDF-звіти та резервне копіювання даних.

3.2 Опис сторінок застосунку

Застосунок містить чотирнадцять сторінок, розділених на публічні, користувацькі та адміністративні:
–	LoginPage / RegisterPage – публічні сторінки автентифікації з валідацією через zod та react-hook-form. Переключатель мови доступний без авторизації. Після логіна автоматичний редирект на /dashboard або /admin залежно від ролі.
–	DashboardPage – головна після входу. Відображає 4 метрики (всього/норма/увага/критично), сітку карток рослин PlantCard з кольоровим StatusChip, BarChart активності сенсорів за тиждень, кнопку експорту в PDF.
–	PlantsPage – список рослин з пошуком (useDebounce), фільтром за статусом та сортуванням з урахуванням локалі через localeCompare.
–	PlantDetailPage – детальна інформація про рослину, SensorReadingCard з поточними показаннями, AreaChart (Recharts) за вибраний період (день/тиждень/місяць) з лінією оптимального значення, ThresholdSlider (зберігається у localStorage).
–	AddPlantPage / EditPlantPage – єдина форма з режимом за наявністю :id. PlantTypeSelector завантажує типи з API.
–	ProfilePage – редагування імені та прізвища, зміна пароля (currentPassword + newPassword + confirmPassword).
–	SettingsPage – перемикач мови UA/EN, кнопка виходу.
–	AdminDashboardPage – метрики по всій системі, графік активності, швидкі посилання на адмін-розділи.
–	UsersPage – MUI DataGrid всіх користувачів з пагінацією, сортуванням через localeCompare, CRUD через модалки, зміна ролі.
–	AllPlantsPage – DataGrid всіх рослин системи з ім'ям власника (user_id маппується через useGetUsersQuery), повний CRUD.
–	PlantTypesPage – CRUD типів рослин з полями optimal_humidity, optimal_temperature, optimal_light, watering_frequency.
–	SensorsPage – DataGrid сенсорів, перемикач is_active, повний CRUD.
–	BackupPage – Export JSON всіх даних / налаштувань, Import JSON з ConfirmDialog, LinearProgress та лічильником imported/failed.

3.7 Прийняті інженерні рішення

RTK Query baseQuery з обробкою 401. Базовий запит у baseApi.ts автоматично додає заголовок Authorization: Bearer {token} до всіх запитів через prepareHeaders. Токен береться з Redux Store або з localStorage (резервний варіант). При отриманні 401 диспатчиться logout() який очищає токен та isAuth. ProtectedRoute при наступному рендері перенаправляє на /login.

Рольова авторизація через AdminRoute. Окрім ProtectedRoute (перевіряє isAuth), адміністративні сторінки обгорнуті AdminRoute який перевіряє user.role === 'admin'. При LogIn, якщо роль admin, DashboardRedirect автоматично перенаправляє на /admin замість /dashboard.

Повна інтернаціоналізація (i18n). Застосунок підтримує 191 перекладений ключ в uk.json та en.json. Хук useFormatters повертає formatDate / formatDateTime через date-fns з локалями uk та enUS, що забезпечує регіонально-коректне форматування дат. Функція sortStrings застосовується як sortComparator у DataGrid для коректного сортування кирилічних рядків через localeCompare. При зміні мови через i18n.on('languageChanged') автоматично оновлюються атрибути document.documentElement.dir та lang.

Генерація PDF через @react-pdf/renderer. PDF-звіти генеруються декларативно через React-компоненти PlantReportPDF та DashboardReportPDF. Для підтримки кирилиці зареєстровано шрифт NotoSans через Font.register. Хук useExportPDF передає вже перекладені рядки у PDF-компоненти, що забезпечує локалізацію PDF відповідно до поточної мови інтерфейсу. Готовий PDF скачується через file-saver.

Резервне копіювання даних (Backup/Restore). Сторінка BackupPage збирає дані з усіх ендпоінтів через Promise.all та формує JSON-файл з полями exportedAt, version та data (users, plants, plantTypes, sensors, sensorData). При імпорті JSON обробляється послідовно: plantTypes, потім plants, потім sensors. Кожна запис обгорнута в try/catch, ведеться лічильник imported/failed. LinearProgress показує прогрес, snackbar повідомляє підсумок.

Розрахунок статусу рослини (calculatePlantStatus). Функція порівнює поточні показання сенсорів з оптимальними значеннями типу рослини. Якщо відхилення перевищує 10% (DEVIATION_THRESHOLD) для 2 і більше показників – статус critical, для 1 – attention, для 0 – normal. Результат відображається кольоровим StatusChip на картках рослин.

Архітектура компонентів. Кожен реюзабельний компонент розміщений у власній папці ComponentName/ з файлами ComponentName.tsx та index.ts (re-export). HTTP-запити виконуються виключно через RTK Query хуки у src/api/ – в компонентах та сторінках прямих fetch/axios відсутні. Всі форми реалізовані через react-hook-form з zod-схемами валідації.

Реалізовано чотирнадцять сторінок з чітким розподілом на користувацький та адміністративний інтерфейси. Застосунок взаємодіє з серверною частиною системи через захищений REST API з JWT-автентифікацією та автоматичним обробленням 401-помилок.
Дотримано принципи чистої архітектури: RTK Query відповідає за всі HTTP-запити, Redux Toolkit за стан аутентифікації та UI, react-hook-form з zod за валідацію форм, TypeScript strict mode забезпечує типову безпеку без використання any.

1. Запит (prompt) щодо підтримки кирилиці у @react-pdf/renderer:
Я розробляю веб-застосунок на React + TypeScript з генерацією PDF-звітів через @react-pdf/renderer 4.5.1. При спробі відрендерити текст українською мовою у PDF отримую порожні квадрати замість символів. Як правильно підключити шрифт із підтримкою кирилиці? Архітектура: хук useExportPDF збирає дані та передає їх у React-компоненти PlantReportPDF та DashboardReportPDF. PDF завантажується через file-saver.
Отримана відповідь:
Для підтримки кирилиці у @react-pdf/renderer необхідно зареєструвати шрифт через Font.register до першого використання PDF-компонентів. Рекомендується використати шрифт NotoSans, який має повну підтримку кирилічних символів та доступний через Google Fonts CDN. Font.register викликається один раз на рівні модуля, поза компонентами. У стилях документа слід явно вказати fontFamily: 'NotoSans' для всіх текстових елементів. Хук useExportPDF повинен передавати вже перекладені рядки через t() у PDF-компоненти, щоб локалізація відповідала поточній мові інтерфейсу незалежно від мовних налаштувань браузера.
2. Запит (prompt) щодо коректного сортування кирилиці у MUI DataGrid:
Я використовую MUI DataGrid v6 у React-застосунку з локалізацією UA/EN через react-i18next. При сортуванні текстових колонок з українськими значеннями порядок сортування некоректний — кирилиця сортується за кодами символів. Як реалізувати локалезалежне сортування у DataGrid з урахуванням поточної мови інтерфейсу?
Отримана відповідь:
Для коректного сортування кирилічних рядків у MUI DataGrid необхідно визначити власний sortComparator для текстових колонок. Функція sortComparator повинна використовувати String.prototype.localeCompare з передачею поточного locale з i18n.language. Щоб уникнути дублювання коду, рекомендується винести цю логіку у хук useFormatters як функцію sortStrings: (a, b) => a.localeCompare(b, i18n.language). Ця функція потім передається як sortComparator у визначенні колонок DataGrid. При зміні мови інтерфейсу хук автоматично повертає оновлену функцію з новим locale, що забезпечує коректне сортування без додаткових дій.

Лістинг Б.2 – authSlice.ts (Redux Toolkit slice автентифікації):

1  import { createSlice, type PayloadAction } from '@reduxjs/toolkit';
2  import type { User } from '@/types';
3  import { TOKEN_KEY } from '@/utils/constants';
4  
5  interface AuthState {
6      token: string | null;
7      user: User | null;
8      isAuth: boolean;
9      isInitializing: boolean;
10 }
11 
12 const initialState: AuthState = {
13     token: localStorage.getItem(TOKEN_KEY),
14     user: null,
15     isAuth: false,
16     isInitializing: true,
17 };
18 
19 const authSlice = createSlice({
20     name: 'auth',
21     initialState,
22     reducers: {
23         setCredentials(state, action: PayloadAction<{ user: User; token: string }>) {
24             state.user = action.payload.user;
25             state.token = action.payload.token;
26             state.isAuth = true;
27             localStorage.setItem(TOKEN_KEY, action.payload.token);
28         },
29         setUser(state, action: PayloadAction<User>) {
30             state.user = action.payload;
31             state.isAuth = true;
32         },
33         logout(state) {
34             state.user = null;
35             state.token = null;
36             state.isAuth = false;
37             localStorage.removeItem(TOKEN_KEY);
38         },
39         setInitializing(state, action: PayloadAction<boolean>) {
40             state.isInitializing = action.payload;
41         },
42     },
43 });
44 
45 export const { setCredentials, setUser, logout, setInitializing } = authSlice.actions;
46 export default authSlice.reducer;

Лістинг Б.4 – plantStatus.ts (розрахунок статусу рослини):

1  import type { Plant, SensorType } from '@/types';
2  import { DEVIATION_THRESHOLD } from './constants';
3  
4  export type PlantStatus = 'normal' | 'attention' | 'critical';
5  
6  export function calculatePlantStatus(
7      plant: Plant,
8      latestReadings: Partial<Record<SensorType, number>>,
9  ): PlantStatus {
10     if (!plant.plantType) return 'normal';
11     const { optimal_humidity, optimal_temperature, optimal_light } = plant.plantType;
12 
13     const deviations: number[] = [];
14     if (latestReadings.humidity != null)
15         deviations.push(Math.abs(latestReadings.humidity - optimal_humidity) / optimal_humidity);
16     if (latestReadings.temperature != null)
17         deviations.push(
18             Math.abs(latestReadings.temperature - optimal_temperature) / optimal_temperature,
19         );
20     if (latestReadings.light != null)
21         deviations.push(Math.abs(latestReadings.light - optimal_light) / optimal_light);
22 
23     const outOfRange = deviations.filter((d) => d > DEVIATION_THRESHOLD).length;
24     if (outOfRange >= 2) return 'critical';
25     if (outOfRange === 1) return 'attention';
26     return 'normal';
27 }

39  const CustomTooltip = ({ active, payload, label, unit, typeLabel }: CustomTooltipProps) => {

42              <Box
43                  sx={{
44                      bgcolor: '#1A1A1A',

56                      {unit}
57                  </Typography>
58              </Box>
59          );
60      }
61      return null;
62  };
63  
64  const PERIOD_FORMAT: Record<string, string> = {

69  
70  export const SensorChart = ({ data, type, period, optimalValue }: SensorChartProps) => {
